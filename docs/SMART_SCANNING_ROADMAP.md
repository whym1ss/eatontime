# Eat on Time — умное сканирование товара и срока

> Статус на 1 августа 2026: клиентская часть P0–P3 реализована, кроме
> собственных QR-наклеек (исключены по решению владельца проекта). Open Food
> Facts и локальные функции работают непосредственно в приложении. Для
> Национального каталога, официального импорта фискальных чеков и отзывов
> партий реализованы клиентские интерфейсы безопасных серверных шлюзов; ответы включатся
> после выдачи доступа провайдерами и настройки серверных секретов.
> Неофициальные API намеренно не используются.

## Цель

После одного наведения камеры приложение должно заполнить максимум полей:

- название, бренд и категория;
- масса/объём и количество;
- точный или предполагаемый срок;
- рекомендуемое место хранения;
- фото продукта и источник полученных данных.

Если точность недостаточна, приложение не выдаёт догадку за факт, а показывает
пометку «Проверьте» и оставляет пользователю одно простое подтверждение.

## Что уже есть

- `mobile_scanner` читает EAN-13, EAN-8, UPC-A, UPC-E и Code 128.
- Сначала используется ранее добавленный товар с тем же штрихкодом.
- Затем выполняется поиск в собственной таблице `product_catalog` Supabase.
- Из каталога уже подставляются название, бренд, категория и `default_days`.
- Если точных данных нет, категория и срок оцениваются локальным
  `ProductMatcher`.

Для QR и кодов маркировки нужно добавить форматы `qrCode` и `dataMatrix`.

## Главный принцип: каскад источников

1. **Локальная история пользователя.** Самый быстрый и персональный источник:
   как пользователь называл товар, где хранил и какой срок выбирал.
2. **Собственный проверенный каталог Eat on Time.** Нормализованные результаты
   прошлых подтверждений с версией и источником.
3. **«Честный ЗНАК» / Национальный каталог.** Авторитетная карточка российского
   товара по GTIN при наличии официального партнёрского доступа.
4. **Open Food Facts.** Открытый каталог еды по штрихкоду для названия, бренда,
   категории, размера упаковки, изображения и состава.
5. **OCR лицевой стороны.** Название, бренд, объём и подсказки хранения с фото,
   если товар отсутствует в каталогах.
6. **OCR даты на упаковке.** Точный срок конкретной единицы товара.
7. **Категорийная эвристика.** Только последний fallback с явной пометкой
   «примерный срок».

Ответы источников объединяет не UI, а единый `ProductResolutionService`. Он
возвращает каждое поле вместе с источником, временем получения и уверенностью.

## «Честный ЗНАК»: как использовать правильно

Официальная документация содержит True API и API Национального каталога.
Национальный каталог умеет искать карточки по GTIN, однако запросы требуют
`apikey` владельца товара либо Bearer-токен ГИС МТ. Приватные методы True API
также работают с аутентификационным токеном и ролевой моделью.

Следствия для проекта:

- ключ или токен нельзя хранить в Flutter-приложении;
- запросы должны идти через Supabase Edge Function / отдельный backend;
- перед разработкой нужно уточнить возможность регистрации Eat on Time как
  партнёра или интегратора и разрешённый потребительский сценарий;
- нельзя использовать неофициальные reverse-engineered endpoint мобильного
  приложения «Честный ЗНАК»;
- нельзя показывать «товар подлинный» или статус оборота без официально
  разрешённого метода и корректной трактовки ответа.

Сам Data Matrix можно разобрать локально и достать GTIN, серийную часть, партию
и дату, если соответствующие поля действительно присутствуют. Форматы кодов
зависят от товарной группы, поэтому отсутствие даты внутри кода — нормальный
случай; тогда включается OCR упаковки.

Официальные материалы:

- [раздел для разработчиков «Честного ЗНАКа»](https://docs.crpt.ru/gismt/%D0%A0%D0%B0%D0%B7%D0%B4%D0%B5%D0%BB_%D0%B4%D0%BB%D1%8F_%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%87%D0%B8%D0%BA%D0%BE%D0%B2/);
- [API Национального каталога](https://docs.crpt.ru/gismt/API_%D0%9D%D0%9A/);
- [форматы передаваемых кодов маркировки](https://docs.crpt.ru/gismt/%D0%A4%D0%BE%D1%80%D0%BC%D0%B0%D1%82%D1%8B_%D0%BF%D0%B5%D1%80%D0%B5%D0%B4%D0%B0%D0%B2%D0%B0%D0%B5%D0%BC%D1%8B%D1%85_%D0%BF%D0%BE%D0%BB%D1%83%D1%87%D0%B0%D0%B5%D0%BC%D1%8B%D1%85_%D0%9A%D0%9C_%D0%9A%D0%98/).

## Open Food Facts: быстрый второй источник

Официальный API v3 поддерживает чтение товара по штрихкоду через
`GET /api/v3/product/{code}` и выбор только нужных полей. Для запросов следует
передавать идентифицирующий `User-Agent`, корректно обрабатывать отсутствие
товара и кэшировать результат.

Нужные поля: локализованное название, бренд, категории, количество/объём,
фото упаковки, ингредиенты и пищевая ценность. Дату конкретной упаковки этот
каталог не заменяет.

При использовании нужно выполнить требования лицензий: база опубликована под
ODbL, содержимое — Database Contents License, изображения — CC BY-SA; в
приложении потребуется атрибуция и проверка условий повторного использования.

Официальные материалы:

- [получение продукта по коду](https://openfoodfacts.github.io/documentation/docs/Product-Opener/v3/products/get-api-v3-product-code/);
- [рекомендованный сценарий сканирования](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/scanning-barcodes/);
- [требования лицензий](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/license-be-on-the-legal-side/).

## Сценарий «одна камера — два результата»

1. Камера одновременно ищет линейный штрихкод, QR/Data Matrix и текст.
2. После кода приложение мгновенно вибрирует и начинает поиск карточки.
3. Пока каталог отвечает, поверх камеры появляется подсказка
   «Теперь наведите на дату».
4. OCR собирает несколько кадров, ищет слова `годен до`, `употребить до`,
   `best before`, `EXP` и распознаёт дату рядом с ними.
5. Результаты объединяются в preview-карточку:
   - зелёный check — точные данные из кода/даты;
   - синий sparkle — данные каталога;
   - янтарный знак — предположение, которое нужно проверить.
6. Одно нажатие сохраняет продукт. Исправления улучшают собственный каталог.

Для OCR даты нужны:

- голосование по 5–10 последовательным кадрам вместо одного снимка;
- нормализация `0/O`, `1/I`, точек, тире и разных порядков дня/месяца;
- проверка разумного диапазона и даты производства рядом со сроком;
- отказ от автосохранения при нескольких равновероятных датах.

## Модель доверия

Каждое автоматически заполненное поле получает:

```text
value, source, confidence, exact, receivedAt, needsConfirmation
```

Пример приоритетов:

| Источник | Название | Точная дата |
| --- | ---: | ---: |
| Data Matrix с явным полем | высокая | высокая, если дата присутствует |
| Национальный каталог | высокая | обычно не дата конкретной упаковки |
| Open Food Facts | средняя/высокая | нет |
| OCR упаковки | средняя | высокая после проверки контекста |
| История пользователя | высокая для названия | средняя для нового экземпляра |
| Категорийная эвристика | средняя | только примерная |

Источник показывается пользователю по нажатию на маленький badge, но не
перегружает основной экран.

## Дополнительные идеи

### 1. QR-наклейки Eat on Time

Для открытых упаковок, контейнеров и домашней еды приложение генерирует свой QR:
название, дата приготовления/вскрытия, срок, количество и владелец холодильника.
Такой код восстанавливает данные полностью офлайн и может печататься на
маленьком Bluetooth-принтере.

### 2. Срок после вскрытия

OCR ищет фразы «после вскрытия хранить 3 суток» и значок открытой банки. В
карточке сохраняются две даты: заводской срок и срок после открытия. Кнопка
«Открыл сегодня» запускает второй таймер.

### 3. Импорт по QR кассового чека

Отдельно исследовать официальный сценарий ФНС/операторов фискальных данных.
Если разрешённый API доступен, QR чека позволит получить список позиций без
распознавания фотографии. Пока официальные условия не подтверждены, оставляем
существующий OCR чека и не используем неофициальные endpoint.

### 4. Непрерывное сканирование покупок

Режим «разобрать пакет»: пользователь без переходов между экранами сканирует
несколько упаковок подряд. Внизу растёт лента найденных товаров, а даты можно
доснять после всех штрихкодов.

### 5. Умное место хранения

По категории, надписям на упаковке и истории пользователя приложение предлагает
холодильник, морозилку или шкаф. Если выбран другой вариант, срок тут же
пересчитывается.

### 6. Защита от отзыва товара

При официальном источнике можно уведомлять о проблемной партии или отзыве.
Эта функция допустима только с достоверным источником, датой обновления и без
самостоятельных заявлений о безопасности продукта.

### 7. Общий семейный каталог

Подтверждённые исправления пользователей агрегируются только после
нормализации: несколько одинаковых подтверждений повышают уверенность, а
конфликтующие варианты отправляются на ручную проверку. Точные сроки конкретной
упаковки в общий каталог не попадают.

### 8. Офлайн-пакет популярных товаров

Небольшой LRU-кэш и предзагруженный каталог частых GTIN позволяют мгновенно
узнавать товары без интернета. Источник и дата обновления сохраняются.

### 9. Умные подсказки после сканирования

После определения категории приложение может предложить не только срок, но и:

- «заморозить часть» для мяса/рыбы;
- «поставить ближе» для срочного продукта;
- объединить дубликаты одного товара;
- предложить рецепт из продуктов с близкими сроками.

## Архитектура

```text
Camera
  ├─ Barcode/QR/DataMatrix decoder
  └─ OCR date/name/volume
          ↓
ProductResolutionService
  1. local history/cache
  2. Eat on Time catalog
  3. CRPT gateway (server only, if access approved)
  4. Open Food Facts gateway
  5. OCR + local heuristics
          ↓
ResolvedProductDraft + field provenance/confidence
          ↓
One-tap confirmation → local DB → anonymized catalog feedback
```

Внешние запросы лучше агрегировать через backend: он скрывает ключи, приводит
разные ответы к одной схеме, соблюдает rate limits, лицензии и кэширование.
Приложение должно сохранять offline-first поведение при недоступности любого
внешнего источника.

## Этапы реализации

### P0 — быстрый результат

1. Добавить QR и Data Matrix в `MobileScannerController`.
2. Ввести `ScannedCode`, `ResolvedField` и `ResolvedProductDraft`.
3. Реализовать нормализацию EAN/UPC/GTIN и локальный разбор известных полей.
4. Подключить Open Food Facts через gateway с кэшем, timeout и атрибуцией.
5. Показывать источник и уверенность автоматически заполненных полей.

### P1 — точная дата

1. Объединить barcode scanner и OCR в один сценарий.
2. Реализовать много-кадровое распознавание дат и контекстные слова.
3. Добавить состояния «точная дата», «примерный срок», «нужно проверить».
4. Собрать обезличенный тестовый набор разных форматов дат и упаковок.

### P2 — официальный российский каталог

1. Связаться с оператором «Честного ЗНАКа» по партнёрскому/интеграторскому
   доступу и письменно зафиксировать разрешённый сценарий.
2. Реализовать CRPT gateway только на сервере.
3. Кэшировать карточки по GTIN и хранить источник/время обновления.
4. Проверить юридические формулировки и обработку статусов.

### P3 — фирменные возможности

1. QR-наклейки для остатков и приготовленной еды.
2. Срок после вскрытия.
3. Непрерывное сканирование пакета покупок.
4. Импорт позиций по QR чека при наличии официального доступа.
5. Уведомления о партиях/отзывах при наличии надёжного источника.

## Метрики качества

- доля сканирований, где найдено название;
- доля упаковок, где точно найдена дата;
- доля полей, исправленных пользователем;
- среднее время от открытия камеры до сохранения;
- попадание источников: local / Eat on Time / CRPT / OFF / OCR / heuristic;
- false-positive даты — критическая метрика, которую нужно минимизировать;
- процент сканирований, завершённых без ручного ввода.
